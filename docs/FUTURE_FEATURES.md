# EBadge Future Features

A backlog of software features and improvements that can be considered as the project develops.

These are ideas, not a fixed roadmap. Features should be evaluated against the available hardware, firmware architecture, memory, power consumption, and project priorities before implementation.

## Priority 1 — PB Custom Events

Create special badge modes for PB events.

Possible ideas:

* Event-specific screens
* Custom animations
* Event themes
* Event announcements
* Temporary event modes

The goal is to make the EBadge feel connected to PB activities and events.

---

## Priority 2 — Easter Eggs

Add hidden interactions and surprises for members to discover.

Possible ideas:

* Hidden button combinations
* Secret screens
* Small animations
* Hidden games
* PB-specific references

Easter eggs should not interfere with normal badge operation.

---

## Priority 3 — Diagnostic Mode

Add an integrated diagnostic mode for testing the physical badge.

The diagnostic mode could test:

* Display
* All five buttons
* Other available peripherals

The result should clearly indicate whether each test passed or failed.

The diagnostic mode should be designed around the final hardware and verified on a physical EBadge before being considered complete.
